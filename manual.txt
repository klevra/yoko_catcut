2. 설치
═══════════════════════════════════════════════════════════════════════════════

2.1 Docker Desktop 설치
─────────────────────────────────────────────────────────────────────────────

macOS:
  1. Docker 공식 웹사이트 방문: https://www.docker.com/products/docker-desktop
  2. "Download for Mac" 클릭
  3. 다운로드된 DMG 파일 실행
  4. Applications 폴더로 드래그 앤 드롭
  5. Applications 폴더에서 Docker.app 실행

Windows:
  1. Docker Desktop for Windows 다운로드
  2. 설치 마법사 따라 진행
  3. WSL2 백엔드 사용 권장

Linux:
  ```bash
  curl -fsSL https://get.docker.com -o get-docker.sh
  sudo sh get-docker.sh
  ```

2.2 Yoko CatCut 저장소 클론
─────────────────────────────────────────────────────────────────────────────

```bash
cd ~/Documents
git clone https://github.com/klevra/yoko_catcut.git
cd yoko_catcut
```

2.3 OS별 설치 프로그램
─────────────────────────────────────────────────────────────────────────────

application.yml의 runtime.os 값으로 지원 OS를 관리한다.

지원 값:
  ✓ win
  ✓ mac
  ✓ rhel
  ✓ ubuntu
  ✓ docker-image

기본 Docker 실행은 docker-image를 사용한다.

macOS:
  ```bash
  bash install/macos/install.sh
  ```

Windows:
  ```powershell
  powershell -ExecutionPolicy Bypass -File install\windows\install.ps1
  ```

Ubuntu:
  ```bash
  bash install/ubuntu/install.sh
  ```

RHEL/Rocky/Alma:
  ```bash
  bash install/rhel/install.sh
  ```

Docker image:
  ```bash
  bash install/docker/install.sh
  ```

설치 프로그램 공통 동작:
  1. 필수 패키지와 프로그램 확인
  2. 없으면 OS별 설치 명령 실행 또는 설치 안내
  3. 설치 경로 입력
  4. default-user 비밀번호 입력
  5. 계정 파일 생성

OS별 상세 문서:
  - docs/install/macos.md
  - docs/install/windows.md
  - docs/install/ubuntu.md
  - docs/install/rhel.md
  - docs/install/docker.md

2.4 비밀번호 재설정
─────────────────────────────────────────────────────────────────────────────

macOS/Linux:
  ```bash
  scripts/reset-password.sh default-user
  ```

Windows:
  ```powershell
  powershell -ExecutionPolicy Bypass -File scripts\reset-password.ps1 default-user
  ```

비밀번호는 workspace/.system/accounts/users.json에 해시로 저장된다.
신규 계정은 workspace/{account}/lock.lck 파일이 있으면 로그인할 수 없다.
관리자가 lock.lck를 삭제하면 로그인 승인 상태가 된다.

3. 실행 방법
═══════════════════════════════════════════════════════════════════════════════

3.1 GUI를 통한 실행 (권장)
─────────────────────────────────────────────────────────────────────────────

macOS:
  1. Finder에서 yoko_catcut 폴더로 이동
  2. start.command 파일 더블클릭
  3. "이 개발자가 확인되지 않았습니다" 메시지 나타나면:
     - 우클릭 → 열기 선택
     - 또는 보안 설정에서 허용 클릭
  4. 자동으로 브라우저가 열리고 http://localhost:3000 접속
  5. 앱 준비 완료 (약 30-60초 소요)

Windows (PowerShell):
  1. yoko_catcut 폴더에서 우클릭
  2. "PowerShell 여기서 열기" 선택
  3. 다음 명령 실행:
     ```powershell
     .\start.command
     ```

3.2 터미널을 통한 실행
─────────────────────────────────────────────────────────────────────────────

```bash
cd ~/Documents/yoko_catcut
docker compose up --build
```

실행 순서:
  1. 🐳 Docker 이미지 빌드 (처음 실행할 때만, 5-10분 소요)
  2. 🚀 컨테이너 시작
  3. 📡 백엔드 서버 초기화
  4. 🎨 프론트엔드 서버 시작

3.3 실행 후 확인
─────────────────────────────────────────────────────────────────────────────

실행이 완료되면 다음 페이지에 접속 가능:

  🌐 프론트엔드 (Web UI):
     http://localhost:3000 (포트는 `.env` 또는 `application.yml` 설정에 따름)

    🔌 백엔드 API:
      http://localhost:8000 (포트는 `.env` 또는 `application.yml` 설정에 따름)

  📚 API 문서 (Swagger):
     http://localhost:8000/docs

  📖 API 문서 (ReDoc):
     http://localhost:8000/redoc

4. 중지 방법
═══════════════════════════════════════════════════════════════════════════════

4.1 GUI를 통한 중지 (권장)
─────────────────────────────────────────────────────────────────────────────

macOS:
  1. Finder에서 yoko_catcut 폴더 이동
  2. stop.command 파일 더블클릭
  3. 모든 컨테이너 자동 중지

4.2 터미널을 통한 중지
─────────────────────────────────────────────────────────────────────────────

```bash
cd ~/Documents/yoko_catcut
docker compose down
```

또는 Ctrl+C (터미널에서 실행 중인 경우)

4.3 강제 중지
─────────────────────────────────────────────────────────────────────────────

모든 컨테이너 강제 중지:
```bash
docker compose down -v
```

포트 충돌 해결 (같은 포트 사용 중인 경우):
```bash
# macOS/Linux
lsof -i :3000          # 포트 3000 사용 프로세스 확인
kill -9 <PID>          # 프로세스 강제 종료

# Windows
netstat -ano | findstr :3000
taskkill /PID <PID> /F
```

6. 문제 해결
═══════════════════════════════════════════════════════════════════════════════

6.1 "Docker not running" 에러
─────────────────────────────────────────────────────────────────────────────

증상: start.command 실행 시 에러 발생

해결책:
  1. Docker Desktop 애플리케이션 시작
  2. Docker 아이콘이 메뉴바에 표시될 때까지 대기
  3. start.command 다시 실행

6.2 포트 충돌 (Port already in use)
─────────────────────────────────────────────────────────────────────────────

증상: "Port 3000 is already allocated"

해결책:

  방법 1: 기존 프로세스 종료
  ```bash
  docker ps                    # 실행 중인 컨테이너 확인
  docker stop <container_id>   # 컨테이너 중지
  ```

  방법 2: application.yml에서 포트 변경
  ```yaml
  app:
    server:
      backend_port: 8001       # 8000 → 8001 변경
      frontend_port: 3001      # 3000 → 3001 변경
  ```

6.3 브라우저가 자동으로 열리지 않음
─────────────────────────────────────────────────────────────────────────────

해결책:
  1. 수동으로 브라우저 열기
  2. 주소창에 http://localhost:3000 입력
  3. Enter 키 누르기

6.4 느린 초기 로딩
─────────────────────────────────────────────────────────────────────────────

원인: Docker 이미지 빌드 중

대기 시간:
  • 첫 실행: 5-10분 (이미지 다운로드 및 빌드)
  • 이후 실행: 10-30초 (캐시된 이미지 사용)

진행 상황 확인:
  ```bash
  docker compose logs -f backend
  ```

6.5 메모리 부족 에러
─────────────────────────────────────────────────────────────────────────────

증상: "Out of memory" 에러

해결책:
  1. Docker Desktop 설정 열기
  2. Preferences → Resources
  3. Memory 값을 최소 4GB로 설정
  4. Docker 재시작

7. 고급 설정
═══════════════════════════════════════════════════════════════════════════════

7.1 application.yml 설정
─────────────────────────────────────────────────────────────────────────────

파일 경로: ~/Documents/yoko_catcut/application.yml

주요 설정 항목:

```yaml
app:
  server:
    host: 0.0.0.0              # 서버 바인드 주소
    backend_port: 8000         # 백엔드 포트
    frontend_port: 3000        # 프론트엔드 포트

  workspace:
    root_path: ./workspace     # 프로젝트 저장 위치

  storage:
    type: local                # 로컬 또는 nas

  upload:
    max_file_size_gb: 10       # 최대 파일 크기

  model:
    whisper_model: large-v3    # Whisper 모델 (v0.3.0)
    device: cpu                # cpu 또는 cuda
```

7.2 환경별 설정 파일
─────────────────────────────────────────────────────────────────────────────

기본 설정:
  application.yml             (기본)

9. 환경설정(.env) 및 기동 테스트
═══════════════════════════════════════════════════════════════════════════════

9.1 환경변수(.env) 사용
───────────────────────────────────────────────────────────────────────────────
프로젝트 루트에 `.env` 파일을 두면 `start.command`와 `stop.command`, `docker-compose.yml`이 이를 자동으로 로드합니다.
기본 예시는 `.env.example`를 참고하세요. 주요 변수:

- `BACKEND_HOST_PORT`: 호스트에서 열릴 백엔드 포트
- `BACKEND_CONTAINER_PORT`: 컨테이너 내부 백엔드 포트
- `FRONTEND_HOST_PORT`: 호스트에서 열릴 프론트엔드 포트
- `FRONTEND_CONTAINER_PORT`: 컨테이너 내부 프론트엔드 포트

예: `.env` 파일에 `FRONTEND_HOST_PORT=4000`로 설정하면 브라우저에서 http://localhost:4000 로 접속합니다.

9.2 application.yml 업데이터
───────────────────────────────────────────────────────────────────────────────
`application.yml`의 `app.server.frontend_port`는 프론트엔드가 내부에서 바인드하는 포트입니다. `.env`의 `FRONTEND_CONTAINER_PORT`와 일치시키는 것을 권장합니다.

9.3 기동 테스트 체크리스트
───────────────────────────────────────────────────────────────────────────────
아래 순서로 기동 테스트를 수행합니다.

1. 서비스 기동
  - 루트에서 `start.command`를 실행합니다 (더블클릭 또는 터미널에서 `./start.command`).
2. 페이지 접속 확인
  - 브라우저로 `http://localhost:<FRONTEND_HOST_PORT>`에 접속하여 페이지가 로드되는지 확인합니다.
3. 서비스 중지
  - 루트에서 `stop.command`를 실행하여 컨테이너를 중지/제거합니다.

동작 테스트(자동화된 테스트 파일 확보)는 별도 단계로 진행합니다. 테스트 파일이 준비되면  `동작 테스트 체크리스트`에 추가합니다.

8. 자주 묻는 질문 (FAQ)
═══════════════════════════════════════════════════════════════════════════════

Q: 클라우드 스토리지 지원하나요?
A: v1.0.0에서 지원 예정입니다. 현재는 로컬/NAS만 지원합니다.

Q: 여러 사용자 동시 사용 가능한가요?
  A: v0.1.2에서는 단일 사용자 기준으로 설계했습니다.
   v1.0.0에서 다중 사용자 지원 예정입니다.

Q: YouTube에서 직접 비디오 다운로드 가능한가요?
A: v0.7.0에서 지원 예정입니다. 현재는 로컬 업로드만 가능합니다.

Q: 자막 자동 생성 기능은 언제 나오나요?
A: v0.3.0에서 제공 예정입니다 (2026년 6월 말 예상).

Q: 썬네일/숏폼 생성은?
A: v0.5.0-v0.6.0에서 단계적으로 지원할 예정입니다.

Q: 데이터는 어디에 저장되나요?
A: ./workspace/ 디렉토리에 저장됩니다. 필요시 다른 위치로 변경 가능합니다.
